## 2 面板与按需加载

- 左侧为彩色图、深度图、检测叠加图列表；右侧放大当前选项。
- 初次打开不自动选择，无图像订阅、无图像下载。左侧未选择项显示占位图。
- 选中项的小图与右侧大图复用同一 Blob，不额外请求缩略图。
- 每个浏览器仅选择一路，切换时释放旧订阅；不同浏览器可以各自选择，同一路共享编码缓存。
- 暂停、页面隐藏、离开页面释放查看需求；异常退出在 2 秒租约超时后回收。
- 无新帧时返回等待状态并清除旧画面；源恢复后继续预览。
- 默认 5 fps、最大宽度 960 px、JPEG 质量 75；当前相机图像为 640×480。
- 图像列表从 YAML 生成，增加条目并重启即可扩展，不改前端。

相机节点同步增加按需图像发布与检测 JPEG 限频，减少无人查看时的编码工作。相机采集和识别仍持续运行，是独立基础开销。

## 4 资源实测

AGX 当前真实场景，单个查看者，6 秒空闲采样、8 秒彩色预览采样。
CPU 百分比以 **一个逻辑核为 100%**，不是整机百分比；短时结果会随场景和其他负载变化。

| 项目 | 无查看者 | 查看彩色图 |
|---|---:|---:|
| 预览节点 CPU | 0.50% 单核 | 4.00% 单核 |
| 预览节点 RSS 内存 | 68.8 MiB | 70.1 MiB |
| JPEG 图像传输 | 0 | 187.7 KiB/s |
| 实收 JPEG 速率 | 0 | 4.49 fps |
| 相机节点 CPU（采集+识别+图像发布） | 120.5% 单核 | 131.8% 单核 |

预览节点本身开销较小。相机基础负载约为 1.2 个逻辑核，不能将其算作面板空闲开销；开启预览还会增加上游图像转换与 ROS 传输开销。
同一路增加查看者可复用编码，但每个查看者仍增加网络流量；选择不同路则增加对应图像处理。

## 5 使用与扩展

```bash
systemctl --user status chess_robot_preview.service
systemctl --user stop chess_robot_preview.service
systemctl --user start chess_robot_preview.service
```

配置：`src/chess_robot_preview/config/channels.yaml`。
支持 `sensor_msgs/Image` 彩色、32FC1 米制深度、`sensor_msgs/CompressedImage`。
完整启动、构建、添加图像示例见预览包 README。

## 6 验证边界

HTTP 页面和静态资源可访问，内置浏览器已创建标题为“相机预览”的页面，但浏览器自动化控制连续超时。
随后 Computer Use 在 Windows 无法可靠确认当前浏览器 URL，按工具的停止要求终止了界面操作。
因此**真实浏览器的点击切换、暂停、全屏、响应式布局尚未完成视觉验收**；不能把后端 API 验证当作这部分已通过。
前端代码实现这些行为，需用户打开入口作最终界面确认。此次未绕过浏览器工具的停止机制。

棋子识别效果、相机安装视野、手眼/TCP 标定和自动抓取仍不在本轮预览节点验收范围。
