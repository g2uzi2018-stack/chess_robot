识别GPU核验与性能优化（2026-10-31）

阶段说明（2026-10-31审校）：本文保留该阶段的试验结果、编号与配置，不能将其中“当前”视为最终部署。后续局部几何优化见 Notion 识别笔记；最终相机发布与预览见 [720p30验证](xiangqi-camera-30hz-20261031.md)。各阶段实时、离线回放和视频帧率的测量口径分别保留。


结论：此前已经在使用Jetson Orin GPU。原推理调用指定device=0。当前运行结果进一步确认predictor_device、model_parameter_device、boxes_device和masks_device均为cuda:0，fp16=false。tegrastats采样显示GPU活跃度约44%～90%；该数值是整机GPU活动，不单独归属于本任务。

低帧率的原因包含实验脚本开销：每颗棋子都在整幅1280×720图上执行掩膜统计、距离变换和深度筛选；重复绘制并发布了网页没有使用的慢速调试图；ROS接收、Python后处理与GPU任务提交存在额外等待和传输成本。仅GPU启用并不能代表整个处理链路达到同一帧率。

已部署的修改
1. 对实际推理裁剪区域执行掩膜/深度处理，调整内参主点后将像素返回原始图坐标；没有降低imgsz=640，也没有更改模型或相机分辨率。
2. 检测框与掩膜批量从GPU取回，避免逐个实例重复传输。
3. 没有订阅者时，不绘制和发布慢速调试图。网页仍由原有独立C++绘制程序提供。
4. GPU推理/深度计算放入独立spawn进程，ROS接收留在父进程，单个请求在途、保留采集stamp和原有过期/运动检查。
5. 实时JSON新增compute和live_stage_ms，以便直接核对设备、精度及处理阶段耗时。

同一批3个保存样本、每种模式15次预热后测量：
原版FP32：单轮中位数111.0ms。
局部处理优化FP32：单轮中位数73.0ms；检测数量、类别和有效性与原版相同，10个有效位置最大差异约7.9e-17m（数值舍入量级）。
FP16试验：70.2ms，收益较小且部分阈值附近检测数量变化，因此没有部署FP16，仍使用FP32。
上述离线单轮测量不包含完整ROS实时取帧和进程传输，不能直接换算成网页帧率。

最终实时10秒测量：
有效识别75次，即7.5Hz。
GPU推理耗时中位数47.4ms。
含深度/位姿分析的处理耗时中位数86.6ms。
从原始采集stamp到发布的延迟中位数198.0ms。
编号仍为#1～#4。
局域网叠加画面另一次6秒测量约17.4Hz；预览配置上限30Hz，当前全链路尚未达到稳定30Hz。以上均为当时负载下的观测，不是固定性能承诺。

编号维护记录：性能分析期间暂停识别超过了轨迹60秒保留期，曾临时产生#5～#8。已经逐一核对四个新旧位置，唯一匹配的位置差约0.22～0.46mm，再恢复为原#1～#4；真实采集时间未被改写，next_id不回退，映射与原状态均有备份。当前位置仍是表面中心，姿态和类别原有实验限制不变。
