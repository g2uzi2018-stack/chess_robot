# 预览节点 30 Hz 更新

日期：2026-10-25（Asia/Taipei）。本记录取代第一版默认 5 fps 的设置；旧版 5 fps 资源结果保留在原交付记录中。

## 1 修改

- 默认预览频率改为 30 Hz；相机采集原本就是 30 Hz，检测叠加图 JPEG 输出改为跟随相机全速。
- 移除前端 40 ms 最短请求间隔，该限制原本使页面最多只能发出约 25 次图像请求/秒。
- 后端编码采用相位累计的限频时钟，允许少量输入抖动，避免近似 33.3 ms 的帧间隔被误判而隔帧丢弃。
- 对已知 `source_fps=30` 的三个相机输出，30 Hz 预览直接逐帧处理，不再对同频输入重复限频；未知帧率来源仍保留限频保护。
- 请求携带上一帧序号；缓存序号相同时，最多等待 50 ms 新帧，避免独立轮询时钟错相漏帧。
- HTTP 监听使用可唤醒的 socket poll，兼顾空闲占用和局域网响应延迟。
- 彩色和深度预览新增相机侧按需 JPEG 输出，预览节点直接转发未超尺寸的 JPEG，避免原始大帧传输与重复编码。原算法图像和 32FC1 米制深度接口保留。深度 JPEG 仅用于伪彩色显示。
- 保留未选择项不订阅、不编码、不传图；大小图共用一次传输；暂停/后台/关闭释放需求。

## 2 验证

构建通过，原视觉算法 8 项单元测试通过；配置扩展、源断流/恢复与过期帧拒绝回归通过。真实 Windows → AGX 局域网收帧测试通过，每路采样约 10 秒：

| 图像 | 实收不同帧的速率 | JPEG 图像流量 | 预览进程 CPU | 预览 RSS |
|---|---:|---:|---:|---:|
| 彩色 | 29.68 fps | 0.97 MiB/s | 33.3% 单核 | 67.3 MiB |
| 深度伪彩色 | 29.40 fps | 0.56 MiB/s | 46.3% 单核 | 68.4 MiB |
| 检测叠加 | 29.72 fps | 1.67 MiB/s | 27.2% 单核 | 69.6 MiB |

测试期间共 2–3 个查看 token 在线（包含测试客户端），CPU 为整个预览进程的使用量，包含其他查看者，不是单个画面的增量；一个逻辑核满载记为 100%。相机进程另约 122–124% 单核。图像流量仅为本次测试连接收到的 JPEG 负载，不含 HTTP/TCP 开销或其他查看者的流量。
30 Hz 是目标，相机、ROS、系统调度和网络会有少量抖动；上表为实测收帧率，没有用重复帧凑数。
结果见 `runs/preview-20261025/lan-30hz.json`，测试以每路至少 28.5 个不同 JPEG/秒为近 30 Hz 的通过条件。

测试从当前 Windows 电脑通过局域网访问 AGX，逐帧检查 JPEG 格式和递增帧序号；不是仅检查配置值，也不是浏览器 GPU 绘制帧率测试。
采样使用本机 `QueryPerformanceCounter`（分辨率 1e-7 s）；本机 Python 的 `monotonic` 为 15.625 ms 分辨率 `GetTickCount64`，不适合作为 33 ms 节拍的测量时钟。
早期原始大图链路曾测得约 27–29 fps，而压缩检测图接近 30 fps；最终版本因此统一使用相机侧压缩预览。早期结果不代表本版最终性能。
