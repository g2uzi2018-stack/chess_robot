## 1 历史核对与本次改动

- 2026-10-26 的提交 `82bd796` 已将明确授权的现场窗口从 0.1 s 放宽到 0.2 s。
  原约 146 ms 空窗原因仍未定；原始记录与故障结果没有改写。
- 当前安装 `.runtime/arm.yaml` 原为 `feedback.freshness_s: 0.2`，而探索模式
  C++ 校验硬上限也是 0.2 s。仅把 YAML 改成 1.0 会在启动时被拒绝。
- 反馈接收还共用 `controller.timeout_ms=500` 的整次读取期限，会在达到 1 s
  之前报错。本次只让反馈接收期限覆盖所选反馈窗口，不改变 dashboard 命令超时。
- 当前安装及随包 exploration 配置设为 1.0 s，探索模式上限改为 1.0 s；
  commissioning 的 0.1 s 上限与通用 hardware 默认值保持不变。

这是反馈状态的容忍时效，并非把反馈频率改成每秒一次。真实空窗超过 1 s
仍会使参考失效。相比旧窗口，反馈丢失的判定可能最多晚约 800 ms；非法帧、
连接断开、时间戳回退、关节/相位跳变仍按原规则拒绝。重复旧帧既不刷新状态，
也不重新开始整次读取期限。ServoJ ACK 0.15 s、停止 ACK 1500 ms、普通命令
超时 500 ms、运动/到达/扭转限制均保持原值。
