# 相机与位姿职责拆分

> 历史阶段记录：此版本仍由相机发布预览 JPEG，面板只有两项。当前已将压缩/伪彩色移入预览，并恢复检测结果订阅占位；以[当前报告](../preview-owned-20261025/REPORT.md)为准。

日期：2026-10-25（Asia/Taipei）。

## 1 当前职责

- `chess_robot_vision / vision_node` 仅负责 D405 采集、彩深对齐、畸变校正、图像/内参及采集帧信息发布。
- 圆检测、中心小圆片深度估计、表面点反投影和对应旧消息/测试已移除；不再发布 `/vision/candidates` 与 `/vision/debug/image/compressed`。
- 新的 `/vision/frame_info`（`FrameInfo`）只保留同帧 Header、彩色/深度帧号、SDK 时间戳及时间域、Z16 深度换算系数、采集有效性和说明。
- 后续位姿节点尚未实现；推荐输入为同时间戳的校正彩色图、对齐 32FC1 米制深度和 CameraInfo，FrameInfo 用于状态与同步追查。
- 相机没有输出目标位置/姿态或相机到机械臂的手眼 TF。JPEG 仅供显示，深度颜色不用于度量计算。
- 深度显示参数改名为 `preview_min_depth_m` / `preview_max_depth_m`，只影响伪彩色，不截断算法用深度。
- 面板暂保留彩色、深度两项，后续位姿结果图可通过 YAML 新增。

## 2 验证

- 相机包重新构建，旧构建/安装目录已移入 `runs/camera-io-20261025/migration/` 保存；干净安装后仅登记 FrameInfo，未残留候选消息文件。
- 两项标定映射测试通过（CTest 包装统计为 3）；原 6 项圆检测/深度估计测试随算法一起移除，历史 8 项结果保留为历史证据。
- 稳定相机观测通过：180 组图像/内参/帧信息/两路 JPEG 同时间戳；FrameInfo 接收年龄 P99 约 20.9 ms，旧两话题发布者均为 0。
- 相机冷启动阶段曾发布 `stream_ok=false / no fresh RGB-D frames`；测试单独记录首次有效帧前的启动状态，并要求 5 秒内就绪，之后任何无效采集状态均判失败。本次稳定观测首个有效帧约 30 ms，无无效状态。
- 两路预览的未选择不订阅、点击加载、切换退订、多客户端共享、暂停释放、异常断开租约回收通过；测试使用临时本地端口，不中断用户面板。
- Windows → AGX 局域网实收不同 JPEG：彩色 **29.70 fps**、深度 **29.70 fps**，各采样约 6 秒，目标为 30 Hz。
- 测试时共 2 个查看连接，预览进程约 16.6～39.4% 单核 CPU、68.9～69.8 MiB RSS；相机进程另约 103～114% 单核 CPU。结果随场景/查看者变化，非硬实时保证。
