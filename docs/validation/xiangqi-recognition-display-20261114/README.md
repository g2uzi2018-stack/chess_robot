# 检测图识别与机械臂坐标状态分离（2026-11-14）

用户反馈：当前检测图几乎全是 `PRED`。现场最初截图确认为 `PRED(base)`，并非仅靠日志推断。

## 原因与处置

- 初始采样：32 枚棋子的类别、相机几何均有效；机械臂被动反馈已停约 19 小时，控制器 192.168.30.234 的 ARP 为 INCOMPLETE，29999/30004 不通。旧渲染器把任何未通过基座显示条件的检测统称 `pred(...)`。
- 用户确认控制箱开机、网线连接后，网络恢复，30004 收到 1440 字节反馈，场景重新获得有效基座坐标，原来的全屏 `PRED(base)` 消失。期间没有修改网络设置、发送机械臂命令、重启机械臂驱动或恢复运动参考。
- 当前机械臂控制 API 仍报告运动参考无效；实时测量坐标可显示不等于运动或抓取已就绪。本次不恢复参考，也不进行运动。
- 新画面直接显示当前帧的中文棋名、红黑阵营与轮廓；未知类别显示“待认”，几何未通过只在该子旁显示“深度待定”或“不完整”。顶部独立显示识别、深度和基座计数。
- 保留原图像/检测时间、关节反馈新鲜度、关节顺序、速度和位置一致性条件。只有这些条件与单子基座资格同时成立才显示真实 track ID；不补造 ID，不沿用旧坐标，不改变识别模型或几何阈值。
- 顶部始终说明“仅显示测量，不代表可抓取”。移除遮挡棋盘的 12 行诊断表。
- 热路径从 YAML 解析改为数据原有格式 JSON 的 JsonCpp 解析，中文棋子标签启动时缓存。部署已存在 JsonCpp、OpenCV freetype 和 Noto CJK 字体，无额外系统软件安装。
- 渲染服务与当前相机使用相同的大图 DDS 配置。

## 实测

同一现场棋盘、1280×720 / 30 Hz，相机与识别服务未重启。

| 项目 | 结果 |
|---|---|
| 旧渲染刷新率，35 秒基线均值 | 16.7136 Hz |
| 新渲染刷新率，60 秒均值 | 30.0005 Hz |
| 识别测量发布，60 秒 | 1785 个独立帧，29.8994 Hz |

| 场景坐标图像时间至接收 p50 / p95 | 267.64 / 292.03 ms |

这里的分类有效比例不是人工标注准确率。新的画面标签不表示几何、运动资格或外部测量精度提高。当前仍有约 1.6% 的单子几何观测未通过，画面如实提示。

现有 `recognition_hz` 是渲染器收到场景消息的频率，包含坐标处理，与上游纯识别测量发布率不是同一个值。画面“识别 Hz”沿用此计数；不能据此断言模型实际运行速度只有该值。相机空间测量主题本来不携带基座资格，其 base_valid_fraction=0 不代表场景坐标失败。

对当前 135129 字节的场景消息各解析 50 次：YAML 平均 21.2998 ms，JsonCpp 平均 3.88971 ms。临时 C++ 对比程序及目录已自动删除，只保留结果 JSON。
