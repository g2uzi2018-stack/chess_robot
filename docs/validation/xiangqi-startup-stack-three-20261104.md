# 启动张爪、Home与三颗叠放调度（2026-11-04）

## 程序行为

实体执行入口按设备前检→张爪→Home→完整抓放前检→扫描→三颗抓放/叠放→Home运行。启动张爪用独立配置`startup_open_raw=1000`，允许释放此前夹持物，收到新的真实张开完成反馈后才回Home。当前抓放标定缺项不会拦截已通过设备前检的启动张爪/Home，但仍会阻止后续扫描和抓放。

设备故障、参考或反馈失效、未停稳、夹爪未初始化等条件仍退出。Home保留只规划与执行核对；低位若不满足普通Home规划规则，会停止，不强行执行或自动构造撤离路径。故障分支不自动张爪或Home。只读/只规划/演练模式不触发启动动作。

默认`max_pieces=3`。每颗重观后抓取、抬升、移动到固定叠放XY，再逐层承托确认、释放、撤离和放稳核对；全部通过才增加层数并退役原位置。第二层、第三层理论目标各加13mm，裸桌理论堆顶base_z依次为3/16/29mm，名义TCP仍须叠加标定偏移，不能直接把这些堆顶数值当TCP。

## 封装

| 方法 | 职责 |
|---|---|
| `Demo.prepare_startup` | 设备前检、启动张爪与起始Home |
| `Demo.return_home` | 起始/结束Home业务 |
| `Demo.scan_workspace` | 扫描及扫描结束Home/停稳核对 |
| `Demo.grasp_piece` | 单颗新鲜重观、对齐、下降、夹取和抬升 |
| `Demo.place_piece` | 转移、放置、释放、退出、放稳和层数提交 |
| `Demo.stack_pieces` | 连续三颗调度，已放源位置排除 |
| `Demo.run` | 顺序调度和统一异常退出 |

## 本轮验证

在内存中运行业务流程和Action替身，不创建ROS节点或硬件连接，没有持久化测试源码或冒烟测试。

- 启动已有夹持物时，仍先张爪，再Home，再扫描；真实适配器接受持物初态并校验新的张开Action反馈。
- 设备前检、张爪、Home、抓放前检、扫描各自失败时，不进入后续业务，不自动重试。
- 扫描未回Home时不抓取。
- 使用先前扫描的候选作合成输入，完整三颗流程通过，选择三个不同源位置，确认层数为1/2/3、理论堆顶为3/16/29mm；输入和标定为合成演练，不冒充实体执行。
- 第二层放稳核对失败时，只保留已确认第一层，不抓第三颗，不自动开爪或Home。
- 修改Python编译、JSON解析及改动文档相对链接检查通过。

本轮只修改程序与文档，没有启动/重启现场主控或执行实机动作。完整抓放配置与三颗绑定审查仍须补齐；历史单颗抓取成功不代表三颗实体叠放已经验收。[多次高度量测](xiangqi-height-measurements-20261104.md)已补齐，并分别记录张爪、闭爪和单点候选高度，未转换成未经量测的通用TCP偏移。
