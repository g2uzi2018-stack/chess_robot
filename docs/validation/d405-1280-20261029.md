# D405 1280×720 启动失败排查与 848×480 验证（2026-10-29）

## 结论

- **1280×720 彩深双流尚未修复**。1280 的 Z16 深度单流 @30 可采 40 帧，1280 彩色单流 BGR8 @30 在 UVC probe/commit 控制传输处被设备 STALL，SDK 报 RS2_USB_STATUS_PIPE。此证据把问题缩小到 1280 彩色 UVC 启动；尚未区分固件 5.16.0.1 与 librealsense 2.58.1 RSUSB 的兼容性。
- SDK 确实枚举 1280×720 的 Color BGR8/RGB8/YUYV 和 Depth Z16（30/15/5 fps），且 DEBUG 显示请求已成功映射为 YUYV+Z16。不能把外层 Failed to resolve 错误理解为未提供该模式。
- 848×480 @30 的独立 SDK 与原 vision_node 都实采成功。原节点同位对比的检测与重投影误差较优，正式源/installed YAML 已改为 width848、height480、fps30。未改 SDK、固件、节点二进制、内核、相机选项或机械臂。
- 正式组合服务首次直接 restart 未启动成功，自动回滚640；改为 stop、等待2秒、start 后 848 成功。这个等待是本次实测有效的设备释放间隔，不能保证解决所有启动异常。正式三路预览（彩色、深度、检测叠加）均验证为848×480且至少3个不同sequence。
- 本工作不代表重新对焦或完成手眼标定。D405无可用对焦控制；识别收益主要来自已存在的 board refinement，分辨率收益有限。

## 环境与操作边界

AGX Ubuntu22.04 aarch64 / ROS2 Humble / OpenCV4.5.4，librealsense2.58.1 用户前缀 /home/kuang/.local/realsense-2.58.1，RSUSB 后端。D405 serial323622271784、firmware5.16.0.1、USB3.2（之前sysfs实查5000M）。未控制、Enable、Stop、移动或连接机械臂接口；观察位由父任务维持，约30.5cm。所有SDK探针仅在组合相机服务停止且确认无原vision_node后独占运行。每个窗口有EXIT恢复；只读诊断overlay一直订阅ROS，不打开USB。

usbfs_memory_mb 读值16，但本次没有NO_MEM证据，未修改全局USB参数。未升级固件、硬件重置设备或改变USB拓扑。

独立SDK的sdk640/和sdk848/另保存未经几何校正BGR图、原始Z16、对齐Z16、source intrinsics和frame时间域。离线rectify_offline依据与节点相同的calibration.cpp校正；offline-comparison.json只是各一个SDK帧的补充，不取代上述多帧统计。SDK frames.csv的epoch浮点时间受C++默认打印精度限制，不适合毫秒差分析；capture.json及ROS CSV保留足够精度。SDK帧号/尺寸证据仍有效。

The parent task also independently ran the real C++ product detector_probe on node848/evidence/color.png: 85 ChArUco corners, reprojection RMS 0.23450980796 px. Metadata was adapted only by forming K from the capture fx/fy/ppx/ppy and using zero D for the already rectified image. Supporting evidence: runs/handeye_refine_20261029/product848/. This is one product-detector frame, supplementary to the multi-frame Python statistics above.

## 正式848持续与网页验证

正式切换脚本deploy848.sh保留640备份，有失败自动回滚；verify_preview.py旁路读HTTP，三路各验证>=3个不同sequence，实际848×480。preview848-verification.json和preview848-{color,depth,detection}.jpg保留结果；preview848-first-failed.json保留首次restart失败现场。

随后8秒旁路ROS观察：live848/summary.json，171配对、57次检测、无invalid、source严格单调；refine marker中位51（50–53）、角点81（77–86）、RMS中位0.241px（0.216–0.292）。三路网页及overlay仍正常。有限样本和best-effort观察器不能证明连续无丢帧30Hz：这次最大配对间隔400ms，可能包含观察器/检测负载造成的丢样，不应隐去。

正式服务最终主PID1360220，vision1360245，preview1360247；见service_final_848.txt与service_final_status.txt。overlay仍为独立只读订阅者，不是位姿控制/标定成功证明。
