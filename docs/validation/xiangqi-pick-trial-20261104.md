# 单颗红卒抓取与20mm抬升验证（2026-11-04）

## 结果与适用范围

在用户授权的候选高度下，另一位置的红卒完成实际抓取、竖直抬升约20mm及停稳。夹爪反馈 `GRASPED`，`position_raw=322`、`grip_status=2`，未报告掉落；用户目视确认：“非常好,非常稳定的抓取了”。代码提交为 `209205b`。

本次只证明该红卒、该位置及固定朝向下的单次抓取。记录结束时保持夹持，未松爪、未叠放、未带物回Home；这是当时的状态记录，不是当前硬件状态查询。完整自动抓放和连续叠放尚未验收。

## 扫描、重观与抓取高度

完整量测过程见[夹指高度量测汇总](xiangqi-height-measurements-20261104.md)，包含多次张爪与完全闭爪量测，不以张爪读数推定固定TCP补偿。

- 先竖直撤回普通安全高度，受控重启候选机械臂程序并恢复原参考和绕转历史，再执行17点扫描、返回Home。扫描状态为 `PARTIAL`，得到8个目标候选；不等于确认全部物理棋子，已被用户拿走的原黑卒位置被排除。
- 另一黑卒的近距离分类复核不一致，拒绝下降与合爪。红卒重观中无有效基座变换的帧保留为拒绝记录，继续等待合格的独立新帧；两秒、至少20帧、同epoch/类别、帧间隔和稳定性检查保留。
- 预抓对齐后再次重观。下降XY取实际停稳位置，并要求与重观棋心相差不超过3mm；下降保持固定XY和朝向。
- 候选名义TCP基座Z为 **-0.005235731876821386m**，取先前观察高度再低1mm；该值不是指尖距桌高度，也不是完整TCP标定。抓取目标XY约为 `(0.266324, -0.715282)m`，观测棋面半径约18.997mm。
- 新夹持反馈后竖直抬升约20mm，持续核对持物反馈，并获用户目视确认。裸桌base_z=-0.010m、棋厚13mm只作本批次背景，不据此直接生成所有位置或叠层抓放高度。

本次使用独立候选安装 `runs/table_contact_20261104_review/install` 和 `table_contact` profile；原默认业务入口仍引用原发布安装，不能直接假设已切换到候选驱动。实际命令保留在 `runs/pick_trial_20261104_01/run-grasp-trial-aligned.sh`；它绑定历史目标、授权文字和输出路径，仅作证据，不应直接重放。

## 视觉停稳计时修正

`stable_observation.py` 原来用主机网络收包间隔估算关节速度，成批到包会造成误判。现改用控制器毫秒时间戳求间隔，保留速度阈值、反馈新鲜度和有效时间间隔检查。1000帧真实停稳数据回放：原逻辑7帧误判，修正后0帧；注入运动仍拒绝。该回放属于先前执行证据，本次提交收尾没有重跑硬件动作。

现场视觉通过隔离源码副本和临时服务覆盖运行该修正，提交不自动替换冻结生产工件。同批提交中的ROI分组与batch功能仍属未部署实验，默认legacy/batch1；不能把本次抓取当作实验推理方案上线验收。

## 叠放前仍需完成

完整 `demo.current.json` 的measured字段仍有缺测，单次成功没有自动填成通用标定。还需核实裸桌落点、支承/释放和撤离空间、被持棋子及增长棋堆的碰撞包络，并把已量测数据接入抓放流程。先进行受监督第一层放置及两颗叠放验证，再决定是否扩展连续任务。

现有目标局部3mm活动夹指净空候选保留普通部件20mm规则，详见[净空候选报告](table-contact-3mm-20261104.md)。该模型间隙不代表实物误差已达到3mm。
