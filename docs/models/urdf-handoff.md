# 给后续 AI / 工程师的 URDF 接力说明

请先读 `docs/models/urdf-workflow.md`，再接手具体模型。以下内容可作为新任务的起始说明。

> 任务是调整与验证机器人描述文件，不是默认执行真实机器人运动。
>
> 先确认当前实物版本、模型用途、工作目录/Git 状态、原始文件 SHA 和单位来源。先运行网格清点与分量三视图，不能根据文件名认定“支架”“夹爪”或“整机”。
>
> 工具：`inspect_mesh.py` 读取网格；`derive_mesh.py` 按显式配置生成派生件；`inspect_urdf.py` 读取纯 URDF、计算 FK、生成 PNG、可选指定对 FCL 扫描。使用各自 `--help`，依赖见 `requirements-geometry.txt` / `requirements-collision.txt`。缺依赖/不支持类型必须说明，不可把未运行当通过。
>
> 人/AI 应明确法兰面、夹持槽/垫片、link 原点、visual origin、TCP 和相机参考系。把每个偏移标为“CAD 基准”“实测”“沿用”或“待确认”。不能通过缩放几何来凑齐装配，不要重复计算已经包含在网格中的安装板厚度。
>
> 修改 Xacro 源及显式安装参数，生成 URDF；保留原始网格和改动 diff。派生网格写入来源/变换信息，不覆盖原件。候选平面/连通分量只提供证据，不能自动当作零件语义或安装基准。
>
> 跑 `check_urdf` 和本项目 `check_models.py`，然后生成默认、正负方向小变化、全开/半开/近闭合姿态的 visual 与 collision 图。核对关节轴、mimic、限位、TCP 方向、是否有固定/活动重复几何。
>
> 若你有图片读取能力，用它实际查看 PNG 并记录观察；如果没有，请把 PNG 交给用户/工程师看，标记“待人工看图”，不能声称已经确认图像。
>
> 对预期会接触/不应接触的 link 对分别记录结果。FCL 离散扫描只覆盖指定对和样本，不能提升为整机或真实轨迹安全结论。不要用关闭全局碰撞或大幅扩大所有碰撞体来掩盖根因；SRDF/ACM 每个忽略对要有固定连接/接触等理由。
>
> “文件能读”“CAD 对齐”“离线局部检查”“实机 TCP 标定”“任务轨迹验收”要分别报告。若缺独立安装件、单位、实际失败姿态或测量，先完成不依赖它们的工作，再提出具体的数据需求。
>
> 结束时提供：改动文件、源哈希与单位、安装变换依据、命令和原始结果、图像、测试范围、未完成项。模型改动后重跑历史失败案例。只有实际做过的步骤才能标成完成。

## 本项目额外事实

- 当前组合入口：`src/chess_robot_description/urdf/nova5_with_ag95.urdf.xacro`。
- 当前固定附件来源是用户提供的 20260117 v2 文件；旧 `new_jiazhua1.STL` 是另一代相机与整套夹爪复合模型，仅作追溯。
- 新附件已包含夹持底座，组合入口 `include_base_geometry=false`，防止与通用 AG95 base 重复；独立夹爪保留通用底座。
- 模型上限 0.94 rad、CAD 下零额外安装 Z、200 mm 抓取参考点只适用于本例，不是其他机器人的默认答案。
- 原有附加盒和蓝色薄片已按用户要求删除；用户曾遇到虚实不一致导致自碰撞，此历史问题仍需用实测和实际失败姿态回归验证。
- 机器人业务/控制代码使用 C++；这些 Python 文件仅为离线描述工具，不要把它们扩展为未经要求的硬件控制入口。
