# 运行日志

本页说明工作区开发版本的实际日志行为。规则来源为 [通用约束 1.2](https://app.notion.com/p/4159f9a4e09e812e861aef2c51155df8)；本页不复制完整规范。

## 位置、格式与等级

从项目根目录 `source tools/env.sh` 后，ROS 日志写入 `log/YYYY-MM-DD/`，日期按 Jetson 的系统时区确定。
控制台格式为 `Unix秒 [等级] [ROS日志名] 事件摘要 参数`。时间来自系统时钟，以 UTC 的 Unix 纪元为基准；不使用可暂停或回退的 ROS 仿真时间。
日志正文中的 `stamp_ns` 是业务采样时间，不能当作日志写入时间。

当前仍使用 ROS 原生日志后端：磁盘文件名由进程生成，**尚未实现通用约束要求的 `log_<功能模块>.log` 合并命名**。
`ROS_LOG_DIR` 只控制目录，不能据此宣称已按功能合并文件。现场冻结服务仍使用原部署的日志入口，本页修改不切换现场服务。

| 日志名 / 功能 | 内容 |
| --- | --- |
| `vision_node` / 相机 | 基础 RGB-D 获取、相机配置、帧不可用及恢复 |
| `xiangqi_perception`、`xiangqi_scene` / 棋子感知 | 相机测量、基座变换与稳定观察的统计、异常 |
| `chess_robot_arm` / 机械臂 | 动作错误、检查点保存及恢复 |
| `xiangqi_tracking_preview` / 识别显示 | 叠加输入解析异常及恢复 |
| `xiangqi_scan_controller`、`xiangqi_pick_stack_controller` / 任务调度 | 扫描、抓放、设备准备的阶段与结果；辅助函数使用调用节点的日志 |

默认使用 INFO 等级，DEBUG 内部细节按需开启。任务级失败记 ERROR，正常观察等待、目标未出现不改成 WARN/ERROR。
现有命令行工具的 JSON、CSV 最终结果仍是工具输出，不作为运行日志改写，避免破坏调用方解析。

## 高频输出与重复异常

| 功能 | 当前输出方式 |
| --- | --- |
| 感知、场景统计 | 沿用 3 秒周期，仅在有发布记录时输出累计帧数、状态、拒绝总数和数据文件位置；不打印完整观察结构 |
| 相机不可用、识别显示输入解析失败 | 首次立即记录；同原因持续发生时最多每 2 秒汇总一次 |
| 机械臂检查点保存失败 | 首次立即记录；同原因持续发生时最多每 5 秒汇总一次 |
| 感知测量编码、场景测量解析异常 | 首次立即记录；同对象、原因和影响持续发生时最多每 3 秒汇总一次 |
| 扫描、抓放和设备准备阶段 | 每次实际阶段变化及时记录；保留已有 task_id，参数限于定位需要的标量 |

异常摘要包含原始原因、实际影响、累计次数、首次与最近发生的 Unix 秒。
原因变化时先保留上一段统计，再立即记录新原因；成功完成相应操作后记录恢复，下一次异常重新计数。
统计周期只控制日志，不改变 Topic 发布、相机轮询、识别计算、机械臂控制或恢复条件。
“恢复”仅表示对应帧处理、输入解析或保存操作成功，不代表整个机器人已经完成任务或可以运动。

## 完整资料与定位

感知的 `perception-latest.json`、场景的 `live-latest.json` 和任务结果保留在各自选择的 `runs/<批次>/`。
它们是测量快照或任务复核资料；日志只引用其位置，不复制大数组、图像或所有下游输出。
任务事件仍保留原有 `events.jsonl` 供该批次复核，ROS Topic 和事件数据格式不变。

排错先按模块和已有 task_id / 操作编号定位，再核对结果文件和上下游的真实状态。
引用错误证据时给出实际日志文件及核对过的行号；收到目标、下发命令、动作结果分别代表不同阶段。
