# 机械臂防绕线策略：设计建议

日期：2026-10-24。本文保留早期需求与物理线缆标定建议；全臂几何旋转策略现已[实现](../../src/chess_robot_twist/README.md)，定义见[扭转模型](rod-twist-definition.md)。物理线缆力学/允许范围仍未标定。2026-11-02起日常Home与历史基准分开，以下历史中的Home/线缆自然参考均应按其上下文区分。

## 1 日常目标与历史参考

- 当前日常目标源为 `config/arm/home.yaml`，参数 `home.joint_positions_rad`；`home_reference.json`记录与目标匹配的采集来源。
- 扭转历史基准为 `config/arm/twist_reference.yaml`，参数 `reference.joint_positions_rad`。原2026-10-24参考角度约 `[79.4900,16.9600,83.3900,-10.3500,-90.0000,-3.6500]` 度继续仅作为历史几何基准，旧采集证据见[冻结记录](../validation/home-reference-2026-10-24.md)。
- 更新日常目标不更改历史基准、完整展开角或检查点identity；到了新Home也不清零。具体采集、校验与加载流程见[当前操作](../operations/arm-quickstart.md)。
- 几何基准并不自动证明真实线缆中性，也不代表270°/360°已通过物理范围标定。真实更换历史基准需要独立物理校准和历史重建流程。

## 2 需求的准确含义

末端回到相同的旋转矩阵，并不表示线缆回到了相同状态。旋转 0° 和 360° 的末端朝向相同，绑在线缆上的扭转可能相差一圈。单独记录末端 yaw 或“末端 yaw - J1”会丢失圈数，也不能表达腕部多关节翻转。

应记录带圈数的六轴角度及其相对 Home/线缆自然参考的有符号偏移。正向转动后再反向回到原位，偏移应减少；不能把每段运动的绝对路程相加当作扭转量。原始反馈若存在回绕或历史中断，需要明确恢复参考，不能凭猜测补圈数或在软件重启时自动归零。

这些角度是线缆风险的可观测代理，不是线材真实扭矩或张力。实际走线跨越多个关节，弯折、长度、固定点和腕部姿态都会影响风险；需要以现场布线确定约束范围。

## 3 可以复用的成熟基础

1. **厂家 IK 的就近参考选解**：本项目已实测 `InverseKin(...,useJointNear=1,jointNear={...})`。从当前姿态、Home 和合适分支产生候选，先验证目标精度，再过滤并排序。无需为这一需求立即更换原厂 IK。
2. **有界角度处理**：[ROS angles 源码](https://github.com/ros/angles/blob/ros2/angles/include/angles/angles.h) 中的 `shortest_angular_distance_with_large_limits` 支持超出 ±π 的关节区间。它可帮助选取合法的等价目标角，不能替代累计状态记录；不可把全部反馈简单归一化到 ±180°后丢弃圈数。
3. **路径约束**：[MoveIt 概念文档](https://moveit.ai/documentation/concepts/) 提供关节、姿态和自定义约束。这些机制适合将来接入全场景规划；约束模型本身不会识别真实线材走线。
4. **IK 的附加代价**：[MoveIt 的 Kinematics Cost Functions](https://moveit.picknik.ai/main/doc/how_to_guides/kinematics_cost_function/kinematics_cost_function_tutorial.html) 展示了最小关节位移等二级目标，可借鉴到厂家 IK 候选排序。目标位姿精度和硬限制先满足，代价不能把硬越界变为“代价较高但仍执行”。

早期评估曾以[pick_ik](https://github.com/PickNikRobotics/pick_ik)的关节居中和位移代价作比较参考，本工程未引入它。本页保留设计来源，不把早期记录当成其当前维护状态或新的依赖选型结论。

## 4 建议的第一版机制

在机械臂节点内实现一个独立 C++ 策略模块，无需再增加运行节点：

1. **状态**：真实六轴角度、可信的圈数/参考状态、相对 Home 的有符号偏移、新鲜度和参考有效性。
2. **硬过滤**：硬件位置限位、经现场确定的线缆关节活动范围，以及路径上的必要耦合限制。先不把未测得的 ±270°或 ±360°当作安全范围。
3. **候选排序**：优先保持当前 IK 分支和连续性、减少无谓整圈与腕部翻转；在可行解之间权衡接近当前状态、接近 Home、远离限位。偏好回正应使已有偏移减少，不固定为某个左右方向。
4. **路径与执行检查**：检查预抓转移、竖直下降和退出的中间状态，而不只看终点。SDK 的就近逆解只是一次计算的选解规则，不能据此假定所有控制器内部路径都满足同一约束。执行监控不能替代路径检查。
5. **恢复方式**：需要解扭时，在具备空间余量的位置规划回中性姿态，或报告需要人工整理线材；不在棋子附近突然旋转，也不因到达 Home 就抹去真实历史。

推荐组合：厂家 IK/运动接口 + 成熟的限位/角度/约束方法 + 针对本机绑线的轻量策略。若后续需要复杂绕障或严格全路径约束，再接入 MoveIt；目前不为防绕线一项立即引入整套规划系统。
