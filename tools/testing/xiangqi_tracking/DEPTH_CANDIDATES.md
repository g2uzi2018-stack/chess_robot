# 深度候选检测：配置与当前边界

此方案用同一采集时刻的对齐深度和相机内参拟合桌面，以到桌面平面的垂直距离寻找凸起物体，再对候选 ROI 调用现有棋子模型。候选扫描不绑定背景或物体颜色，也不调用全图 YOLO。棋盘作为另一层支撑面处理；棋盘上的棋子高度相对棋盘计算。

本轮仅提供 `depth_shadow` 验证模式，默认生产仍使用原 `yolo` 策略。shadow 的检测、分类和耗时可用于分析，但 `full_scene_coverage` 和 `classification_complete` 始终为 false，不能产生合格场景快照或运动/夹取资格。它不代表机械臂移动扫描已经验收。

## 配置文件

复制 `depth_candidates.example.json` 为当前视角的独立 JSON 文件，再填写内参、相机会话、工作区和裸桌种子。示例故意保留 `K=null`、两个多边形为 `null` 和会话占位符，不能直接作为现场配置加载；其中没有借用历史现场的 K 或多边形。

JSON 分为三层：

| 层级 | 用途 |
|---|---|
| `qualification_mode` | 必须为 `"shadow"`，明确实验用途。 |
| `view_binding` | 当前视角的标识、相机会话、图像尺寸和内参绑定。 |
| `detector` | 桌面拟合、物体尺寸估值、候选和质量门限。 |

参数保存在 JSON，修改厚度不需要改 Python。运行时通过以下环境变量选中模式和配置文件；这两行只声明设置，不启动服务：

```bash
export XIANGQI_CANDIDATE_MODE=depth_shadow
export XIANGQI_DEPTH_CONFIG=/absolute/path/current_view.json
```

不设置 `XIANGQI_CANDIDATE_MODE` 时，保持原 `yolo` 行为。加载缺失、非法 JSON、非法参数或缺失的多边形会报错，不会悄悄回退为全图 YOLO。配置内容的 SHA256 写入运行身份；运行中改文件会使配置资格失效，需要重启验证实例。

## 必须填写的当前视角信息

| 字段 | 格式和含义 |
|---|---|
| `view_binding.view_id` | 为本次静止视角起名，便于追溯；名称本身不能证明相机没有移动。 |
| `view_binding.camera_epoch` | 使用当前采集数据 `metadata.camera_epoch` 的实际值，不能沿用另一会话。 |
| `view_binding.image_size` | `[宽, 高]`，当前接线支持 `[1280,720]`。 |
| `view_binding.K` | 复制同帧相机内参的 9 个数，按行展开：`[fx,skew,cx,0,fy,cy,0,0,1]`。焦距和主点单位为像素。 |
| `detector.image_size` | 必须与 `view_binding.image_size` 一致。 |
| `detector.workspace_polygon_xy` | 至少 3 个 `[x,y]` 像素点，围住本视角中需要检查的桌面区域，排除桌外。坐标原点在图像左上角。 |
| `detector.table_seed_polygon_xy` | 至少 3 个 `[x,y]` 像素点，选取工作区内部、可见且确认为裸桌的区域，不能包含棋盘或棋子。用于声明哪个平面才是桌面。 |

工作区应覆盖待检查的物体，不能为了让数据通过而只框住四颗棋子。桌面种子不是按“最大平面”自动猜出的结果：如果把棋盘面或桌外地面选作种子，拟合成功也不证明桌面身份正确。

像素多边形只适用于当前视角。相机 epoch 和 K 的核验能发现部分输入变化，无法发现同一相机会话内机械臂改变相机位姿。因此本轮强制 `pose_binding_verified=false` 和 shadow。相机移动后必须重新验证工作区/裸桌种子；不能把一组多边形当成通用扫描标定。

## 厚度估值与深度单位

所有 `_m` 字段均用米；`0.008m=8mm`，`0.010m=10mm`。输入必须为与彩色图同帧、同尺寸、已对齐的 `float32` 米制深度图。高度使用相对于参考平面的有符号垂距，不能用一个固定 Z 值替代倾斜桌面的平面。

| 字段 | 示例值 | 含义 |
|---|---:|---|
| `expected_piece_thickness_m` | 0.008 | 用户估计的棋子厚度，记录在诊断中；不用于伪造或重写实测深度。 |
| `expected_board_thickness_m` | 0.010 | 用户估计的棋盘厚度，参与广阔板面高度的一致性检查；不相符时保留为未解决区域。 |
| `min_object_height_m` | 0.008 | 本次希望能分辨的最小物体高度。这里仍是估值，需要实物测量确认。 |
| `min_height_m` | 0.004 | 前景高度阈值的实验起点；对桌面和棋盘上的凸起分别使用。它不是棋子厚度。 |
| `max_height_m` | 0.080 | 允许凸起高度的上限，超出时不能作为正常完整候选。 |
| `single_piece_diameter_m` | null | 实测单棋子直径，用于排查多个棋子连接成同一候选。尚未测量时保留 null，候选不能因面积够大就获得完整几何资格。 |

若棋子放在约 10mm 厚棋盘上，其顶面相对桌面可能约为 18mm，但相对棋盘仍约为 8mm。不能把“高于桌面”全部当作独立棋子，也不能直接把棋盘整体当成一颗棋子。

示例把前景阈值设为 4mm，仅用于尝试分辨 8mm 目标。算法还比较裸桌面残差：最小可分辨高度至少为 `max(min_height_m, 2×桌面残差95分位)`。若该值达到或超过 8mm，即使有些凸起被检出，也不能宣称已检查完整。应检查深度质量、视角和物理尺寸；不能仅降低质量门槛换取通过。

## 其他参数及单位

示例给出的门限均为验证起点，尚不构成全棋盘、桌边、遮挡或移动扫描的适配承诺。

| 字段 | 单位 | 用途 |
|---|---|---|
| `min_depth_m` / `max_depth_m` | 米 | 有效深度范围。 |
| `plane_inlier_m` / `max_plane_rms_m` | 米 | 桌面拟合点的残差容限与平面均方根残差上限。 |
| `min_seed_inlier_fraction` | 0～1 比例 | 裸桌种子的最小平面内点比例。 |
| `min_seed_pixels` / `max_fit_points` | 点/像素数量 | 种子的最少有效支持量与拟合采样上限。 |
| `ransac_iterations` | 次数 | 稳健平面拟合的迭代上限。 |
| `min_facing_cosine` | 无量纲 | 桌面法向相对相机光轴的最低夹角余弦约束。 |
| `min_valid_fraction` | 0～1 比例 | 工作区及种子的最小有效深度比例；深度洞不能被当成空桌面。 |
| `min_candidate_area_m2` | 平方米 | 有实体面积支持、值得做 ROI 分类的候选下限；示例 0.0003m² 为 300mm²。 |
| `max_piece_span_m` | 米 | 单候选允许的最大物理跨度。 |
| `min_board_span_m` / `min_board_area_m2` | 米 / 平方米 | 可能是棋盘的广阔区域尺寸下限。 |
| `board_plane_band_m` | 米 | 板面高度层的分组宽度。 |
| `min_board_planar_fraction` | 0～1 比例 | 区域中板面高度层的最低支持比例。 |
| `min_board_rectangularity` | 0～1 比例 | 板面的矩形填充程度，避免将连接的棋子顶面误作整块棋盘。 |
| `min_component_pixels` | 像素数量 | 最小连通区域支持量。较小区域保留未解决诊断。 |
| `edge_margin_px` | 像素 | 工作区边缘完整性检查的留边距离。 |
| `max_candidates` | 个数，最多300 | 有界输出预算；超过预算会撤销覆盖资格。 |
| `max_components` | 个数，默认4096 | 连通区域分析的资源上限；超限会拒绝覆盖资格，不能把截断后的部分结果当成完整场景。 |
| `median_kernel_px` | 像素，1/3/5 | 深度中值滤波窗口；不修补原始深度洞的有效性。 |

## 读取结果

`depth_scan.valid` 表示裸桌参考平面可用。`depth_scan.coverage_valid` 表示算法对**当前配置工作区**的深度覆盖检查通过，不能理解成整个桌子、桌外或相机未拍到的地方都已检查。

`roi_eligible` 表示候选值得做语义识别，与几何是否完整分别判断。有实体尺寸支持但邻接深度洞的棋子仍可做 ROI 分类，不能靠跳过这些真实棋子报告加速。

`candidate_geometry_valid=false` 表示候选轮廓、接触关系或深度仍有未解决问题。即使 ROI 类别明确、内表面拟合通过，也不能覆盖该几何拒绝。ROI 发现的额外目标没有获得深度工作区准入时，保留为未知。

阅读性能时同时比较真实棋子的类别、漏检、未知、几何资格、网络调用次数和处理耗时；当前 shadow 的场景资格始终为 false。棋盘/棋子厚度估值、噪声分辨率和单棋子直径都应在实验记录中明确，不能只给一个 FPS。
